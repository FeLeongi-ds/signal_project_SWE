# Alert Generation System

The Alert Generation System evaluates patient measurements and creates alerts when a patient's vital signs pass unsafe limits. The central class is `AlertGenerator`, which reads patient records from `DataStorage` and checks each relevant `PatientRecord` against alert rules. These rules may be represented by `AlertThreshold`, allowing different patients to have different safe ranges. This is useful in a hospital context because patients can have different medical histories, risk levels, and monitoring requirements.

When a rule is violated, `AlertGenerator` creates an `Alert` containing the patient ID, condition, timestamp, and severity. The diagram includes `Patient` and `PatientRecord` because every alert must be traceable to the patient and to the measurement that caused it. This supports auditing and helps medical staff understand whether an alert came from blood pressure, oxygen saturation, ECG activity, or another monitored value.

`AlertManager` stores active alerts and dispatches them to `MedicalStaff`. This separates detection from communication: `AlertGenerator` decides whether an alert is needed, while `AlertManager` handles routing. Medical staff receive alerts through `AlertManager` instead of directly accessing alert generation logic. This keeps responsibilities clear and makes the system easier to extend. For example, new alert rules could be added without changing how alerts are delivered, and new staff notification methods could be added without changing the health-condition checks.
